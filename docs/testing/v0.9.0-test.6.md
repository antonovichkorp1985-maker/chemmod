# Проверка ChemMod v0.9.0-test.6 — видимость реактора

Это узкое исправление по пользовательскому отчёту test.5: установленный реактор
был невидим, хотя определялся подсказкой и обрабатывал колбы. Пользователь
подтвердил работу реакции; полная приёмка M3 из этого не следует.

## Установка

Minecraft 1.21.1, NeoForge 21.1.251, Java 21. Сделайте резервную копию мира,
уберите прежний ChemMod JAR и поставьте один и тот же
`chemmod-0.9.0-test.6.jar` на сервер и все клиенты.

Файлы после публикации:
https://github.com/antonovichkorp1985-maker/chemmod/releases/tag/v0.9.0-test.6

Скачайте также `.sha256` и проверьте из каталога скачанных файлов:

```sh
sha256sum -c chemmod-0.9.0-test.6.jar.sha256
```

macOS: `shasum -a 256 -c chemmod-0.9.0-test.6.jar.sha256`.
PowerShell: сопоставьте `.sha256` с результатом
`Get-FileHash .\chemmod-0.9.0-test.6.jar -Algorithm SHA256`.

Формат сохранений относительно test.5 не меняется; нового намеренного сброса
прогресса при переходе test.5 → test.6 нет. Для перехода со старого test.4
по-прежнему действует предупреждение о сбросе неподтверждённого прогресса из
[инструкции test.5](v0.9.0-test.5.md).

## Что проверить

1. Откройте копию мира с уже установленным реактором. Его модель должна быть
   видна, а прежние предметы внутри — сохраниться. Переставлять блок для
   исправления невидимости не требуется.
2. Поставьте второй реактор и проверьте его с нескольких сторон. Сверьте
   выделение и подсказку: видимый блок должен совпадать с выбранным реактором.
3. Откройте GUI, запустите прежнюю тестовую реакцию. Модель должна оставаться
   видимой при работе и после завершения. Для наблюдаемого прогресса пригодна
   обычная горящая furnace; blast furnace завершает маршрут быстро.
4. Сохраните и загрузите мир: видимость и содержимое должны сохраниться.
5. Если невидимость осталась, пришлите скриншот, точную версию JAR, `latest.log`,
   используемые ресурс-паки и шейдеры. Только для диагностики можно сравнить с
   отключёнными шейдерами/ресурс-паками; мы не считаем их виновниками исходного бага.

## Что именно исправлено

`ChemicalReactorBlock` наследовал `RenderShape.INVISIBLE` от `BaseEntityBlock`,
но не имел отдельного block-entity renderer. Наличие JSON-модели и рабочей иконки
предмета само по себе не включало отрисовку установленного блока. Теперь блок
явно выбирает `RenderShape.MODEL` для обоих состояний `active`.

GameTest проверяет этот выбор в мире при переключении состояний и неизменность
block entity/инвентаря. Это **не проверка итоговых пикселей, текстур или шейдеров**;
реальное изображение должен подтвердить клиентский прогон.

## Чего здесь нет

Текстуры и кубическая модель остаются временными. В test.6 **не добавлены**
размещаемые колбы, стойки, мерные цилиндры, спиртовки, газовые горелки/шланги или
нагревательные столы. Они зафиксированы как целевая лабораторная часть в
[ADR-0003](../adr/0003-physical-equipment-and-food-processing.md).
Печь снизу остаётся только временным адаптером тепла M3, а не окончательным
проектом лаборатории. Остальные проверки реактора описаны в
[чек-листе test.5](v0.9.0-test.5.md); модели промышленного оборудования и пищевая
система этим исправлением не реализованы.
