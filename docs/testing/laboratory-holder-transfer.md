# Перенос заполненных держателей — разработка после test.7

**Не входит в опубликованный test.7. Новый релиз не создаётся.** Материалы
публикации по-прежнему отложены. Этот этап расширяет прежнее снятие только
пустых держателей; старые инструкции test.7 сохраняются как история релиза.

## Управление и поведение

- **Shift + ПКМ пустой основной рукой** по стойке/подносу снимает выбранную
  часть одним переносимым предметом, теперь даже с сосудами внутри.
- Обычный ПКМ по-прежнему забирает только один сосуд.
- Переносимый предмет не складывается в стопку. В подсказке показаны занятые
  позиции и названия сосудов, включая их пользовательские имена.
- ПКМ по поверхности устанавливает держатель с новым направлением по взгляду.
  ПКМ по существующей второй части объединяет их в одной клетке с направлением
  уже установленной части. Пустые промежутки в слотах не сжимаются.
- ID переносимого держателя и ItemStack-компоненты сосудов сохраняются; соседняя
  часть и её ID не меняются. Сосудам не добавляется отдельный глобальный UUID.
- Заполненный/упакованный предмет расходуется **даже в creative**, чтобы сам
  маршрут переноса не копировал содержимое. Обычный пустой предмет из creative
  вкладки по-прежнему не расходуется при обычной установке.
- При переполнении инвентаря доставка выдаёт один упакованный предмет на землю,
  а не россыпь сосудов. Обычное разрушение/потеря опоры по-прежнему высыпает
  держатели и сосуды отдельно; аккуратный перенос и разрушение — разные действия.

## Данные и безопасность переноса

`chemmod:packed_laboratory_holder` — сохраняемый и синхронизируемый компонент:
тип держателя, UUID и стандартный Minecraft `ItemContainerContents`.
Допускаются только отдельные сосуды ChemMod в пределах 6/4 позиций. Вложенные
держатели, контейнеры/связки в сосудах, предметы другого типа и стопки сосудов
отклоняются. Ошибочные сохранённые данные не удаляются ради упаковки.

Перед установкой проверяются тип, единичный размер упакованного предмета,
занятость места, опора и права. Альтернативные `BLOCK_ENTITY_DATA`, `BLOCK_STATE`
и `CONTAINER` на предмете-держателе не принимаются как обход пути восстановления.
Снятый/заменённый block entity больше не разрешает извлечение по старой ссылке.

Установка через стандартный путь NeoForge может быть отменена событием
`EntityPlaceEvent`. При восстановлении block snapshots держатель не генерирует
выпавшие копии; проверяются возврат исходного предмета и NBT соседа.
Сохранённая копия переносимого компонента не остаётся в block entity после
установки: рабочие позиции становятся единственным источником содержимого.

Это защита обычных игровых путей, не глобальный реестр собственности. Команды
оператора, сторонний код и намеренное копирование предметов в creative не
объявлены защищёнными от дублирования во всём мире. Произвольные вмешательства
сторонних модов и массовые перемещения конструкций требуют отдельных проверок.

## Автоматические тесты

`LaboratoryHolderTransferGameTests`: 11 тестов — перенос дырявого набора слотов
и имён; NBT/network codec round-trip; заполненная стойка в другой клетке и
ориентации; creative consumption; добавление подноса к соседу; отказы при занятом
месте/неподходящей опоре; неверный тип/стопки/вложенные контейнеры; доставка при
полном инвентаре; реальное Shift-взаимодействие; отмена первой установки и
объединения стандартным событием NeoForge.

Проверка заполненного инвентаря вызывает доставку напрямую: при обычном клике
пустая основная рука обычно уже оставляет свободную ячейку. Это не выдаётся за
проверку сетевой гонки. Кодеки не заменяют настоящего restart и двух клиентов.

## Ограничения и ручная проверка будущей сборки

- В руке/инвентаре пока используется прежняя модель держателя; состав виден в
  подсказке. Отдельный рендер сосудов на переносимом предмете не добавлен.
- Это не интерфейс переносного сундука: сосуды вставляются/вынимаются после
  установки. Автоматизация, хопперы, нагрев и произвольные столешницы не добавлены.
- Новому компоненту нужен новый код на всех клиентах и сервере. Не загружать мир
  с такими предметами старым test.7: откат только через резервную копию. Не
  смешивать старый опубликованный JAR с артефактами рабочей ветки.
- Проверить реальный restart с предметом в инвентаре/сундуке/на земле, перенос
  между клетками, все повороты, два клиента, подсказки, запрет размещения модом
  защиты территории и повторные клики. Ручная приёмка пока не получена.
