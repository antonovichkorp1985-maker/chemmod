# Ориентация лабораторных держателей — разработка после test.7

> Обновление рабочей ветки: Shift-снятие теперь переносит также заполненный
> держатель. См. [этап переноса](laboratory-holder-transfer.md). Ограничение
> «снимать только пустой» ниже относится к исходному этапу разработки.


Новый релиз не создаётся. Изменение находится в рабочей ветке и **не входит в
опубликованный test.7**. Публикация и комплект оформления остаются отложенными.

## Что меняется

- Первый держатель получает одно из четырёх горизонтальных направлений при
  установке, по направлению взгляда игрока (локальный «перед» обращён к игроку).
- Вторая часть в той же клетке наследует ориентацию первой. Добавление подноса
  с другой стороны стола не переставляет уже установленные сосуды.
- Модель блока, позиции/поворот отображаемых сосудов, резервируемые коллизии,
  геометрия для core-проверки и выбор места мышью используют одну систему
  локальных координат. Четыре набора collision shapes кешируются.
- Обычный ПКМ работает с сосудом на выбранном месте. Shift + ПКМ пустой рукой
  по-прежнему снимает только выбранный **пустой** держатель.
- Выбор точки вне отпечатка держателя или в промежутке больше не прижимается
  к крайнему слоту. Неограниченные и NaN-координаты не принимаются.
- Старые block-state сохранения без `facing` должны загружаться в NORTH: это
  историческое расположение test.7. Формат содержимого block entity не меняется.

## Границы

Это четыре поворота всей пары при установке, не свободное размещение/вращение
каждого сосуда и не поворот заполненного держателя инструментом. Block-state
rotation hook предусмотрен для систем, которые вращают состояния, но его тест
не означает совместимость с движущимися конструкциями других модов. Специальная
механика зеркального отражения асимметричного содержимого не добавлена.

Требование полной верхней опоры, два фиксированных держателя в одной клетке,
условный резервируемый объём вместо точной формы прутьев и отсутствие переноса
заполненного подноса целиком остаются. API Chisels & Bits не подключён.

## Автоматическая проверка

`LaboratoryHolderOrientationGameTests` — семь новых тестов:

1. Независимые ожидаемые координаты для четырёх поворотов и обратное преобразование.
2. Все 40 положений сосудов выбираются правильным индексом и лежат внутри
   коллизии своего держателя, не соседа; core принимает повернутые отпечатки.
3. Четыре поворота в мире не заменяют block entity, не меняют NBT содержимого/ID;
   ориентация проходит NBT round-trip block state.
4. Историческое состояние без `facing` получает NORTH и сохраняет обе части.
5. Настоящий путь установки предметом учитывает взгляд игрока, а второй
   держатель не поворачивает первый и не изменяет его ID/содержимое.
6. Снятие пустого подноса при каждом повороте не затрагивает заполненную стойку.
7. Промежуток, отсутствующая часть, точки вне отпечатка и NaN не выбирают сосуд.

Python-проверка ресурсов перебирает все 16 сочетаний `facing/rack/tray` и
проверяет, что multipart JSON включает ровно нужные модели и углы. Наличие
ресурсов и совпадение математических координат не являются GPU-тестом.

## Ручная проверка будущей сборки

На полном каменном блоке поставить пары с четырёх сторон. Проверить, что сосуды
не висят сбоку от стойки, а этикетки поворачиваются вместе с ней. Добавить поднос
с противоположной стороны; содержимое не должно сдвинуться. На каждом повороте
проверить все позиции, выбор мышью, снятие пустой части и отказ для заполненной.
Затем проверить настоящий restart, выгрузку чанка и двух клиентов. Результат
настоящего клиентского прогона пока не получен.
