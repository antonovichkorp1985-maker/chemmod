# Ручная проверка ChemMod v0.9.0-test.4

[`v0.9.0-test.4`](https://github.com/antonovichkorp1985-maker/chemmod/releases/tag/v0.9.0-test.4)
— технический prerelease для player-проверки M3, первого физического Chemical
Reactor. Это **не** отметка о завершении M3: результаты этого чек-листа определят,
можно ли закрыть раздел или нужен следующий test-пререлиз с исправлениями.

> Не используйте `/chem`, команды выдачи, save editor или internal CLI для
> замены пути ниже. В игровом JAR нет команд, которые создают вещества,
> симулируют синтез или открывают discovery.

## 1. Установка

1. Используйте **Minecraft 1.21.1**, **NeoForge 21.1.251** и Java 21.
2. Скачайте со страницы prerelease оба файла:
   - `chemmod-0.9.0-test.4.jar`;
   - `chemmod-0.9.0-test.4.jar.sha256`.
3. Удалите из клиентской и серверной папок `mods` старые `chemmod-*.jar`:
   одновременно должен присутствовать только один ChemMod JAR. На сервере и
   всех клиентах должен быть тот же самый JAR.
4. По желанию проверьте SHA-256:

   ```sh
   sha256sum -c chemmod-0.9.0-test.4.jar.sha256
   ```

   В PowerShell сопоставьте первую колонку `Get-FileHash
   .\chemmod-0.9.0-test.4.jar -Algorithm SHA256` со значением в `.sha256`.
5. Сначала запустите игру без Create. Затем, если в сборке используется Create
   6.0.10, отдельно повторите запуск с ним: Create остаётся optional.

## 2. Успешная физическая партия

В creative test world получите Chemical Reactor, blast furnace, топливо, чистую
100% колбу этанола, copper ingot и две пустые laboratory vial. Поставьте и
разожгите blast furnace, разместите reactor прямо над ней, затем переключитесь
в survival перед работой с машиной.

1. Откройте reactor ПКМ.
2. Положите этанол в **Target**, один copper ingot в **Cat.**, по одной пустой
   колбе в оба **Products**. Co-reactant для этого маршрута не нужен.
3. GUI должен назвать **Alcohol dehydrogenation**. Кнопка `?` показывает
   локализованное объяснение data-owned правила. Статус и progress должны быть
   server-authoritative.
4. Дождитесь завершения. Ожидаются отдельные колбы `C2H4O` и `H2`; исходная
   колба становится пустой, copper ingot остаётся. Смесь вместо двух выходов —
   дефект.
5. После результата проверьте, что discovery появился только вследствие этой
   успешной физической обработки, а не вследствие creative-размещения, просмотра
   GUI, отказа или ручного смешивания.

## 3. Отказы и атомарность

Для каждого случая зафиксируйте содержимое всех слотов до действия и убедитесь,
что оно не изменилось.

- Уберите/погасите heat source: правило может быть названо, но progress остаётся
  нулевым и продуктов нет.
- Уберите copper ingot: reactor сообщает отсутствие катализатора; входы и
  выходы не изменяются.
- Поместите аналитически нечистую колбу либо explicit mixture: reactor не должен
  извлекать из неё чистый компонент, переписывать содержимое или создавать
  продукт.
- Займите product slot неподходящим предметом или заполненной колбой: запуск не
  должен частично потребить этанол.
- На обычной lit furnace дождитесь видимого частичного progress, затем выньте
  или замените input/output vial. Progress обязан отмениться сразу; следующая
  проверка не должна выдать продукт или списать вход.

## 4. Persistence и multiplayer

1. На обычной lit furnace начните частичную партию. Оставьте те же input,
   catalyst, output vials и heat source, перезапустите мир/сервер. Инвентарь и
   progress должны сохраниться; операция может продолжиться только для тех же
   физически валидных слотов.
2. На dedicated server один игрок запускает reactor, второй открывает его во
   время обработки и после завершения. Оба должны видеть согласованные слоты,
   progress, статус, выбранное правило и результаты.
3. Замените/выньте колбу одним игроком во время частичной партии. Второй игрок
   должен увидеть отмену, а после повторного открытия не должно появиться
   продублированного продукта.
4. После успешного результата снова перезапустите сервер и проверьте, что обе
   выходные колбы и discovery не потеряли содержимое.

## 5. Что приложить к отчёту

Для любого дефекта приложите версию и SHA-256 JAR, Minecraft/NeoForge/Java,
список модов, singleplayer/dedicated-server, наличие Create, воспроизводимые
шаги, ожидаемый и фактический результат, скриншоты GUI/слотов и `latest.log`
(а также crash-report при аварии).

## Граница v0.9.0-test.4

Графы, parser, балансировка и core reaction rules проверяет CI/internal CLI, а
не игровые команды. Первый reactor намеренно не обрабатывает explicit mixtures.
Разделение, реакторные пути смесей, фазы и равновесие — следующие слои плана.
