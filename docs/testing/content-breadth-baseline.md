# ChemMod — базовый набор контента: элементы, минералы, названия

**Дата:** 10 октября 2026
**Тип среза:** контент + guard-тесты. Поведение реактора, discovery и оборудования не менялось.

## 1. Зачем

Ответ на вопрос «почему так мало веществ»: узкое место — не модель, а контент.
Идентичность вещества — граф (`docs/architecture.md` §1), свойства выводятся из структуры
(`PropertyEngine`: «All coefficients live in `PropertyRuleSet`, not in named substance records»),
поэтому ширину химии задают три датапак-файла и набор правил, а не список веществ.
До этого среза таблица элементов содержала только 11 неметаллов, нужных органическому срезу.

## 2. Что изменилось

| `ChemItems.MAIN_TAB` | захардкоженный список `TEST_SUBSTANCES` из 11 русских псевдонимов | образцы берутся из справочника; известные соли сортируются по результату ионных правил (растворимые, затем нерастворимые), далее по вычисленному классу `FunctionalGroups`, длине максимального простого пути по C-графу и стабильному ID; каждый образец — вариант общей data-component колбы |

Код: `TrivialNameDirectory.all()` и `CommonSubstances.all()` — read-only доступы к
объявленным меткам. Метки по-прежнему не определяют существование вещества: это только
источник калибровочного списка, поэтому новое название в датапаке само добавляет пробирку.

Creative-вкладка не может перечислить все допустимые молекулярные графы: таких структур
нет конечного каталога, и ChemMod намеренно не регистрирует отдельный item для каждой
молекулы. Она показывает конечные именованные reference samples в одном общем типе колбы;
реакционные продукты получают ту же колбу с динамическим molecular data component. В рамках
этого среза в выборку вошли все именованные species и явные bundled-rule/M3 вещества, а также
все молекулы, которыми `BoilingPointModelTest` проверяет property-модель. Этот последний тест
теперь требует creative reference для каждой входной структуры, чтобы новая validation-молекула
не осталась невидимой в каталоге. Это расширяет конечную проектную выборку, но не утверждает,
что она перечисляет все возможные графы.

Порядок в creative tab выводится из графа, не из таблицы свойств по отдельным солям:
`IonicSolubilityClassifier` извлекает заряд-сбалансированные ионы, распознаёт поддерживаемый
класс аниона и применяет существующее правило `Solubility`; поддержанные references попадают
в группы «растворимые по правилу» и «нерастворимые по правилу». Остальные образцы группируются
по классам `FunctionalGroups`, затем по точной длине максимального простого пути по C-графу.
Подсказка колбы показывает класс, длину цепи и результат/«неизвестно». Это грубые правила
осаждения, не Ksp и не универсальная модель растворимости; нераспознанные ионы и нейтральные
молекулы остаются «неизвестно».

## 3. Что этот срез сознательно НЕ делает

- Новые минералы — данные. У них пока нет блоков, рудогенерации, лута и процессов:
  единственная жила — `chemmod:overworld_native_copper`, единственная материальная цепочка — медь.
- Полная таблица элементов не означает, что все возможные соединения с этими элементами
  заранее заведены как creative-образцы или имеют правила реакции. Реакции остаются
  data-defined и покрывают только заявленные структурные классы; осадки, кислотно-основные
  реакции и восстановление железных руд здесь не подразумеваются.
- Благородные газы добавлены с валентностью 0: инвариант `Element` ослаблен до
  `valences.all { it >= 0 }`, где ноль означает инертный элемент. Такой атом существует как
  одноатомное вещество, не получает неявных водородов и отклоняет любую связь
  (`VALENCE_EXCEEDED`), потому что занятая сумма не может превышать ноль.
- Свойства новых веществ считаются тем же набором коэффициентов (9 энергий связей, 8 вкладов
  в температуру кипения), поэтому у многих неорганических молекул температура кипения и ΔH
  останутся `null` — модель честно не отвечает там, где у неё нет данных.

## 4. Guard-тесты

`core/src/test/kotlin/io/github/antonovichkorp/chemmod/core/ContentCoherenceTest.kt` — 7 тестов:

1. стехиометрия каждого минерала использует только элементы из таблицы (кварц больше не
   проходит молча с неизвестным `Si`);
2. вся периодическая таблица покрыта ровно один раз, валентности и атомные номера согласованы;
3. поляризуемость покрыта по источнику, с честным `null` для Lv;
4. инертные элементы представлены одноатомными графами и отвергают связи;
5. каждая метка разбирается в валидный граф, её `canonicalKey` совпадает с идентичностью,
   все псевдонимы разрешаются в ту же молекулу;
6. именованные вещества различны и доступны через `CommonSubstances`, включая русские aliases;
7. каждый явный species из bundled reaction rules и ключевые промежуточные молекулы M3 имеют
   именованный creative reference vial; ацетальдегидгидрат не смешивается с этиленгликолем.

Дополнительно `ReferenceMoleculeCatalogTest` проверяет длину цепи, графовую классификацию,
сортировку и статусы растворимости. `IonicSolubilityClassifierTest` охватывает модельные salt
pairings, формулы и неизвестные анионы; `BoilingPointModelTest.referenceMolecule` связывает все
property validation examples с каталогом. Проверки не перечисляют все возможные вещества.

## 5. Проверка

Исполняемая проверка — CI (локально JDK нет): модульные тесты `core` и `mod` плюс GameTest-сервер.
Результат зафиксирован в аннотации JUnit соответствующего прогона.

### 2026-10-25 — расширение конечного каталога

В соответствии с выбранной владельцем конечной областью в справочник добавлены все 63 различные
структурные записи, используемые тестами модели кипения (часть записей может обозначать один и
тот же канонический граф); общий каталог теперь содержит 88 именованных образцов. Проверка property-модели сама требует, чтобы
каждая тестовая структура находилась в каталоге. Добавлены graph-derived сортировка и метки
класса/цепи в тултип; растворимость для этих образцов помечена «неизвестна», поскольку модель
растворимости охватывает только выбранные ионные пары для осаждения.

CI run `40144543648` на `873a43e` прошёл: 52 JUnit-класса, 378 тестов, ноль failures/errors.

Это изменение не переносит из M7 дизайнер молекул и не делает каталог перечислением всех
возможных структур. Оно также не закрывает A2 справочник и не является приёмкой M0–M3.

### 2026-10-25 follow-up — salt solubility groups

Добавлены 28 finite salt references, покрывающие ионные правила и структурную проверку аммония.
Общий каталог содержит 116 образцов. `IonicSolubilityClassifier` определяет класс соли из
заряженных компонентов графа, проверяет баланс зарядов и вызывает существующие правила
растворимости; поддержанные случаи сортируются как растворимые/нерастворимые по результату
грубой модели, неподдержанные остаются неизвестными. Заряженные атомы больше не получают
неявные водороды; формулы распознанных солей записываются в порядке катион → анион.

Это по-прежнему finite reference catalog, не полный список всех солей или всех графов. CI run `40147051125` на `0a5b375` прошёл. A2 screen, M7 designer и owner acceptance остаются
за пределами этого изменения.
