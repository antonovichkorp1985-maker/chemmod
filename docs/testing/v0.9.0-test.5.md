# Ручная проверка ChemMod v0.9.0-test.5

`test.5` объединяет исправления сохранения партии, интерфейса, discovery и
действий в меню после `test.4`. Это **кандидат для проверки M3**, не объявление
этапа завершённым. Предыдущий релиз и его файлы не заменяются.

Страница сборки после публикации:
https://github.com/antonovichkorp1985-maker/chemmod/releases/tag/v0.9.0-test.5

## 1. Безопасное обновление

1. Остановите игру/сервер и сделайте резервную копию **всей папки мира**.
   Для первого прогона лучше отдельный тестовый мир, не основной survival.
2. Используйте Minecraft **1.21.1**, NeoForge **21.1.251**, Java **21**.
3. Уберите старые `chemmod-*.jar` из `mods`. Поставьте ровно один
   `chemmod-0.9.0-test.5.jar` на сервер и **каждый** клиент. Не смешивайте test.4,
   test.5 и промежуточные CI-сборки: у нового интерфейса есть сетевой пакет,
   которого в test.4 не было.
4. Скачайте рядом с JAR файл `chemmod-0.9.0-test.5.jar.sha256`. Проверьте хеш:

   Linux:
   ```sh
   sha256sum -c chemmod-0.9.0-test.5.jar.sha256
   ```

   macOS:
   ```sh
   shasum -a 256 -c chemmod-0.9.0-test.5.jar.sha256
   ```

   PowerShell (из каталога скачанных файлов):
   ```powershell
   $expected = ((Get-Content .\chemmod-0.9.0-test.5.jar.sha256) -split '\s+')[0]
   $actual = (Get-FileHash .\chemmod-0.9.0-test.5.jar -Algorithm SHA256).Hash
   if ($actual -ine $expected) { throw 'SHA-256 mismatch' }
   'SHA-256 OK'
   ```
5. Проверьте запуск без Create, затем отдельно с **Create 6.0.10**, если он
   используется. Create остаётся необязательным и не встроен в ChemMod.

### Что произойдёт со старым миром

- Предметы, количества веществ, готовые продукты и прежние записи discovery
  сохраняются; идентичность молекул этим релизом не мигрируется.
- **Незавершённая партия из test.4 начнётся заново:** в старом формате нет
  сохранённой привязки прогресса к правилу и точным слотам. Это защитный сброс
  только прогресса, а не расход содержимого колб.
- У готового результата из test.4 может не быть нового отображения «завершено»:
  старое сохранение не содержит подтверждающего снимка слотов. Продукты остаются.
- Партия, начатая уже в test.5, сохраняет привязку и может продолжиться после
  загрузки при тех же слотах и валидных условиях.
- Старые имена операторов сохраняются; открытия не переназначаются. Для чистой
  проверки нового авторства используйте свежую партию с явным изменением слотов.
- Обратный переход на старый JAR на уже изменённом мире не проверен: для отката
  восстанавливайте резервную копию, не перезаписывайте её новым сохранением.

## 2. Основная реакция — сначала этот короткий сценарий

В creative возьмите ChemMod Chemical Reactor, чистую 100% колбу этанола,
медный слиток ChemMod, две пустые лабораторные колбы, обычную Minecraft blast
furnace, топливо и сырьё для плавки (например, raw iron в чистой тестовой среде).
Затем переключитесь в survival для работы с машиной. Это калибровочный тест
реактора, **не доказательство готовой survival-цепочки получения реагентов**.

1. Поставьте реактор **прямо над** blast furnace. Запустите в ней настоящую
   плавку: одно топливо без подходящего сырья не обязано зажечь печь. Она должна
   гореть, а не просто стоять рядом. Начните с ванильного блока, не с аналога TFC.
2. В реактор положите этанол в **Цель / Target**, медь в **Кат. / Cat.**, по
   пустой колбе в оба **Выход / Outputs**. Слоты со-реагентов оставьте пустыми.
3. Должно быть выбрано правило дегидрирования спирта. Дождитесь обработки:
   на blast furnace она быстрая, сервер пересчитывает условия раз в секунду.
4. Проверьте: исходная колба стала пустой; медь сохранилась; появились **две
   отдельные колбы** — `C2H4O` и `H2`. Каждая содержит 1 000 000 мкмоль, если
   исходная калибровочная колба этанола содержала 1 000 000 мкмоль.
5. Несколько секунд ничего не трогайте: статус «завершено», правило и **100%**
   должны сохраняться, а не сменяться ошибкой о нечистой исходной колбе.
6. Заберите продукт: отображение завершения должно сброситься. Пустая исходная
   колба означает ожидание нового входа; повторных продуктов возникать не должно.

## 3. Интерфейс и просмотр открытий

- Проверьте русский и английский языки, несколько масштабов GUI.
- Наведите курсор на длинный статус/название правила: полный текст должен быть
  доступен во всплывающей подсказке. Нажмите `?` для объяснения правила и повторно
  для закрытия. Подписи не должны рисоваться поверх инвентаря.
- До извлечения продуктов нажмите **«Открытия выходных веществ»**. Для каждого
  из двух выходов ожидается формула и сведения о **первом синтезе в этом мире**:
  автор и дата UTC. Это не утверждение, что именно текущая колба первая в мире.
- При повторной реакции уже открытые вещества должны сохранять прежнего автора
  и дату. На чистом мире при первом синтезе ожидается автор, загрузивший партию.
- Извлечение продукта убирает сведения о нём из этого представления. При смене
  колбы старые сведения не должны ошибочно относиться к другому веществу.
- «Ожидание данных сервера» допустимо кратковременно при синхронизации. Постоянное
  ожидание на одинаковых JAR — повод приложить клиентский и серверный логи.
- Просмотр сам по себе не создаёт открытия. Панель показывает только вещества
  **в текущих выходных колбах**, а не весь реестр мира. Пустые выходы до первой
  реакции поэтому не позволяют вручную проверить весь реестр — это отдельно
  покрывают автоматические проверки. Не используйте команды или save editor.

## 4. Количества, стопки и отказы

1. В пустой реактор Shift-click стопку из 16 пустых колб: в каждый выход должна
   попасть одна; у игрока суммарно останется 14. Остаток может переместиться
   между основным инвентарём и хотбаром — важны суммарные количества.
2. Вставьте медь из стопки: в слоте катализатора одна, остаток у игрока.
   Проверьте и обычное размещение курсором, и Shift-click.
3. Заполните инвентарь игрока так, чтобы продукт некуда было положить или
   объединить со стопкой. Shift-click продукта должен оставить его в реакторе.
4. Без горящего источника тепла либо без меди реактор не должен расходовать
   этанол или создавать продукты.
5. На обычной горящей furnace (не blast furnace) начните более медленную
   реакцию. Во время неполного прогресса выньте выходную колбу: прогресс должен
   немедленно отмениться, а этанол — сохраниться. Возвращение колбы начинает
   новую партию, а не достаёт из отменённой готовый продукт.
6. Повторите с явной смесью воды и этанола: реактор не должен выделять из неё
   чистый этанол. Калибровочная смесь доступна в creative.
7. Неподходящий предмет/заполненную колбу меню не должно принимать в выходы.
   Уже занятые продуктами выходы должны блокировать следующую партию до
   освобождения. Не обходите ограничения меню командами ради этого пункта.

Аналитически нечистый вход, повреждённый прогресс и искусственно изменённые NBT
проверяются автоматикой. Не нужно создавать их через редактор сохранения для
ручной приёмки. Если подходящий нечистый образец уже существует в старом мире,
можно отдельно проверить безопасный отказ на копии этого мира.

## 5. Сохранение и настоящий multiplayer

### Перезапуск

1. В test.5 начните частичную реакцию на обычной furnace; сохраните и закройте
   мир/сервер до завершения. Для singleplayer можно сначала поставить игру на
   паузу. Оставьте входы, катализатор и выходные колбы на местах.
2. После запуска инвентарь должен совпадать, а прогресс — продолжаться лишь при
   действующих условиях. Если печь погасла, реакция не должна завершаться сама.
3. После успешной партии ещё раз перезапустите сервер: количества продуктов и
   сведения первого синтеза должны сохраниться. Пока слоты не менялись, новое
   отображение завершения восстанавливается после серверной проверки.
4. Отдельно проверьте копию старого test.4 мира: ожидается описанный выше сброс
   незавершённого прогресса, но не потеря содержимого.

### Два игрока

1. Игрок A загружает слоты при ещё выключенном нагреве. Игрок B только открывает
   окно. Затем включите нагрев: для нового в мире вещества ожидается автор A.
   Само размещение блока или открытие окна не назначает нового автора.
2. Оба наблюдают одинаковые слоты, статус, прогресс и сведения об открытиях.
3. B изменяет слот во время неполной партии: старая партия отменяется. После
   повторной загрузки автор новой партии — последний реальный редактор слотов.
4. **Уже существующее discovery неизменно**: чтобы проверить нового первого
   автора, нужен ещё не открытый продукт или отдельный свежий тестовый мир.
5. Соберите результат, переоткройте окно с обоих клиентов; проверьте отсутствие
   дублирования, лишнего расхода и устаревших сведений у второго наблюдателя.

## 6. Что прислать

Версию JAR и SHA-256; Minecraft/NeoForge/Java; singleplayer или dedicated server;
наличие Create и список модов; обновлённый или новый мир; точные шаги;
ожидаемый/фактический результат; скриншот GUI. При ошибке — `latest.log` клиента
и сервера, а при аварии — crash report. Не присылайте токены или пароли.

## Граница этой версии

Автоматика проверяет ядро, серверные сценарии, меню, кодирование пакетов и NBT.
Это **не заменяет** настоящий restart, рендеринг GUI и два подключённых клиента.
M3 остаётся на приёмке. Реактор по-прежнему рассчитан на отдельные чистые колбы;
новых маршрутов смесей, разделения, фаз, равновесий или моделей машин в test.5 нет.
