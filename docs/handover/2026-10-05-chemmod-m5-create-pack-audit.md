# ChemMod — дополнение к инструкции: M5 и аудит реальной сборки

**Дата:** 5 октября 2026
**Статус:** реализовано, проверено в CI и опубликовано как тестовый prerelease
**Относится к:** `ПЛАН-ДРУГА.md` v1.3; не отменяет и не сокращает его полную спецификацию.
**Граница отчёта:** это исторический M5-аудит Create-интеграции. Он не определяет
молекулярную онтологию, discovery или статус последующих M2-слоёв; для них
действует [`../architecture.md`](../architecture.md).

**Лицензия ChemMod:** `All Rights Reserved`. Исходники разрешено просматривать для оценки, аудита, обучения или личной справки; копирование, модификация, форки, сборка из исходников и распространение без отдельного письменного разрешения запрещены. Пользовательский артефакт — только официальный неизменённый бинарный релиз.

## 1. Что завершено

В ChemMod завершён M5 — **опциональная Create-совместимость для кинетического разделения руды**. Это законченный игровой срез поверх уже существующего полного медного маршрута:

```text
природная медная руда
→ дробление
→ промывка с физическими хвостами
→ промытая дроблёная руда
→ ручное ИЛИ кинетическое разделение
→ медная пыль + отдельная силикатная порода
→ плавка, накопление расплава и точное литьё
→ слиток и формы меди
```

Ручной сепаратор остаётся ранней полноценной ступенью. Create не отменяет его и не создаёт второй таблицы выходов: кинетический сепаратор — автоматизируемый привод того же канонического физического процесса.

## 2. M5: контракт поведения

### Когда адаптер существует

- Поддерживается **Create 6.0.10 для Minecraft 1.21.1 / NeoForge**.
- Create — необязательная зависимость: без него ChemMod запускается как самостоятельный мод, а `kinetic_ore_separator`, его block entity, item и рецепт вообще не регистрируются/не загружаются.
- Create не встраивается в JAR ChemMod. Сохранение обычного ChemMod не получает обязательной зависимости Create.
- При Create рецепт использует один ручной сепаратор ChemMod, две медные пластины ChemMod, вал Create и андезитовый корпус Create.

### Что делает машина

- Вал подключается сверху или снизу. Передняя решётчатая сторона — вход партий, противоположная — выход.
- Минимальное требование — `MEDIUM` Create, то есть значение из реального server-config, а не отдельное захардкоженное число.
- Машина получает 4 stress impact на RPM; работа прекращается при недостаточной скорости, перегрузе сети или при заполненном выходе.
- Вход и выход открыты через обычный NeoForge `ItemHandler`, поэтому подходят воронки и логистика Create. Ввод/вывод также доступны вручную.

### Что никогда не меняется

Перед расходованием входа сервер читает компонент `material_batch` у **конкретной** партии. Затем он рассчитывает результат через `MaterialProcessExports.bundledPartitionProcesses()` и `OreSeparation.separate`, резервирует место для всех результатов и только после этого расходует ровно одну партию.

Следствия:

- нет статического Create-рецепта с фиктивными дропами;
- нет RNG-бонусов, дублирования, потери или создания массы;
- сохраняется фактическая масса меди и **каждой именованной примеси**;
- 65 выходных слотов покрывают первичный продукт и до 64 примесей схемы `material_batch` v2;
- чистота и солёность/тип пробы воды TFC, состав партии и её масса не переопределяются слоем Create.

Код использует только публичные API Create для вала, kinetic network, проверки скорости и stress impact. Код, ассеты, имена механизмов и рецептурные таблицы Create или GregTech не переносились.

## 3. Аудит фактической сборки — не вслепую

Аудит проведён по доступному снимку реального экземпляра в Drive, обновлённому 4 октября 2026: папка `mods`, `config` и мир `Новый мир`.

| Проверенный факт | Результат для ChemMod |
| --- | --- |
| База экземпляра | Minecraft **1.21.1**, NeoForge **21.1.251**, Java 21; соответствует целевой базе ChemMod. |
| Базовый Create | В `mods` находится `create-1.21.1-6.0.10.jar`; версия точно совпадает с M5 compile/runtime-целью. |
| Create server config | Stress включён (`disableStress = false`), `mediumSpeed = 30 RPM`, `fastSpeed = 100 RPM`, лимит — `256 RPM`. |
| Базовая кинетика Create | В том же config `millstone` имеет impact **4**, `crushing_wheel` и `mechanical_press` — **8**. ChemMod выбрал **4**, то есть уровень базовой мельницы, а не тяжёлого пресса/дробильных колёс. |
| TFC | Установлен `TerraFirmaCraft-NeoForge-1.21.1-4.2.11.jar`; он удовлетворяет опциональному диапазону ChemMod `[4,)`. В config активен TFC world preset. |
| Дополнительная техническая среда | Есть GTCEu 7.0.2, Almost Unified 1.4.2, Create New Age и набор Create-аддонов. ChemMod не пытается самовольно перебалансировать или отключать их. |
| Интерфейс рецептов | Установлен EMI 1.1.24 (JEI не найден). Условный рецепт M5 должен проверяться в EMI в реальном экземпляре с установленным Create. |
| Квесты | Установлены FTB Quests 2101.1.36, FTB Library и FTB Teams. В доступном снимке мира найдено состояние игрока без начатых/выполненных задач; определений глав `chapters.snbt` в доступной экспортированной ветке нет. Авторство квестов остаётся за владельцем сборки/другим агентом. |

### Вывод по собственному балансу M5

В этой конкретной сборке `MEDIUM` действительно означает **30 RPM**. Поэтому реальная минимальная нагрузка сепаратора равна `4 × 30 = 120` stress units. При 100 RPM она равна 400. Это намеренно совпадает с уровнем обычной мельницы из **текущего** Create-конфига и заметно ниже дробильных колёс/механического пресса (8).

Для существующей канонической операции разделения с `durationTicks = 300` машина требует `300 × 16 = 4800` единиц работы. При отсутствии перегруза это даёт:

| Скорость сети | Время одной партии |
| --- | --- |
| 30 RPM (минимум данной сборки) | 160 тиков ≈ 8 секунд |
| 100 RPM (`fast`) | 48 тиков ≈ 2,4 секунды |
| 256 RPM (паковый лимит) | 19 тиков ≈ 0,95 секунды |

Таким образом, M5 не требует позднего источника энергии для первой автоматизации, но в производительности награждает уже построенную кинематическую инфраструктуру. При этом он не увеличивает выход меди: ускоряется только физическое разделение партии.

**Решение по итогам аудита:** эти значения оставлены без искусственной правки. Реальные базовые пороги (30/100/256), включённый stress и стоимость 4 подтверждают исходный замысел. Следующая корректировка чисел допустима только после игрового прогона именно этого экземпляра с новой версией ChemMod; это не повод менять баланс всех сторонних модов.

## 4. Проверка и тестовый релиз

M5 проверен в GitHub Actions на коммите `bcf827b`:

1. unit-тесты и компиляция Java;
2. проверка содержимого итогового JAR;
3. headless dedicated-server запуск без Create;
4. отдельный headless dedicated-server запуск **с Create 6.0.10**, подтверждающий фактическую активацию адаптера.

Оба CI-прогона завершились успешно: `37359675548` и `37359683231`. Тег и релиз:

- **`v0.8.0-test.1`** — commit `bcf827b`;
- GitHub prerelease: <https://github.com/antonovichkorp1985-maker/chemmod/releases/tag/v0.8.0-test.1>;
- assets: `chemmod-0.8.0-test.1.jar` и `chemmod-0.8.0-test.1.jar.sha256`.

### Установка в проверяемый экземпляр

1. Удалить прежний `chemmod-0.0.2-test.1.jar` из папки `mods`, чтобы не было двух JAR одного mod id.
2. Скачать JAR и `.sha256` из указанного prerelease; проверить контрольную сумму.
3. Поместить новый JAR в `mods` рядом с уже проверенными `create-1.21.1-6.0.10.jar` и TFC 4.2.11.
4. В мире поставить кинетический сепаратор, подать на верх/низ вал с 30 RPM или выше и проверить одну промытую партию с обычным выходом на противоположной стороне.
5. Убедиться, что масса и список примесей на выходе равны входной физической партии после разделения, а переполненный выход не расходует вход.

## 5. Границы следующего шага

- Pack-wide баланс, изменение конфигов Create/TFC/GTCEu/NuclearCraft и написание FTB-квестов **не входят** в работу ChemMod и не должны выполняться этим модом самовольно.
- Установка GTCEu в этой сборке не превращает ChemMod в копию или обвязку GTCEu. Его система обогащения остаётся только высокоуровневым ориентиром: несколько объяснимых ступеней, материальный баланс, хвосты, масштабирование автоматизации — без переноса кода, данных, названий, идентификаторов, ассетов или таблиц рецептов.
- Следующий крупный игровой срез обязан снова начинаться с проверки данного экземпляра: его актуального mod-list, Create/TFC-конфигов, конфликтов item/tag-рецептов и фактического игрового теста. Нельзя подменять это предположениями по «стандартному» Create.
