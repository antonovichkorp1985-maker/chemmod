## 1. Инвариант: вещество — это граф, а не строка каталога

План (§2, §3, §14) формулирует это так: «вещество = структура», «не «добавить вещество»,
а «добавить элемент/правило» — вещества возникают комбинаторно», «10 элементов, ~30 правил
на старт; всё в датапаках; новый элемент = апдейт контента, не ядра». В ChemMod это уже
закреплено кодом, а не намерением:

| Где | Что именно гарантирует отсутствие перечня веществ |
| --- | --- |
| `core/src/main/kotlin/io/github/antonovichkorp/chemmod/core/model/MoleculeGraph.kt` | Вещество — это `Atom(id, element, formalCharge, explicitHydrogens)` + `Bond(first, second, order)`, `BondOrder` = 1/2/3. Других полей у молекулы нет: ни имени, ни «типа вещества», ни ссылки на каталог |
| `core/src/main/kotlin/io/github/antonovichkorp/chemmod/core/Canonicalizer.kt` | `MoleculeCanonicalizer.canonicalKey(graph)` — Morgan-итерации по (Z, формальный заряд, явные/неявные H, степень, сумма порядков связей) плюс отсортированная часть связей → digest. Комментарий в файле: «The full digest is persisted; the Long form is only a compact display/API value» |
| `core/src/main/kotlin/io/github/antonovichkorp/chemmod/core/CommonSubstances.kt` | «This directory resolves only human names; it never controls the existence of a molecular structure» |
| `core/src/main/kotlin/io/github/antonovichkorp/chemmod/core/material/Definitions.kt` | `ChemicalSpecies`: «The graph's canonical key, not this content ID, is the molecular identity; unnamed molecules do not need a `ChemicalSpecies` entry». `MineralDefinition` = формула + стехиометрия по элементам (+ Mohs). `DepositDefinition` = веса минералов. Сплав/композит — `MaterialSource.Composite(components: Map<MaterialId, Int>)`, то есть карта компонентов, а не запись «сплав X со свойствами Y» |
| `core/src/main/kotlin/io/github/antonovichkorp/chemmod/core/material/MaterialMassComposition.kt` | «Every microgram is named either as primary material or as a known impurity; percentages are derived only for presentation» — чистота это масса, а не поле «сорт» из таблицы |
| `docs/architecture.md` §1 | «Единственная идентичность молекулярного вещества — валидный молекулярный граф»; название, `SpeciesId`, формула и Item ID идентичностью не являются; `ChemicalSpecies` «не образует реестр всех возможных молекул и не может назначать их свойства» |
| `docs/adr/0001-canonical-material-authority.md` | «A valid molecular graph is the authority for molecular identity» (Accepted, updated 2026-10-06) |

Объём контента на 10.10.2026 (посчитано по файлам репозитория):

- `core/src/main/resources/chemmod/elements.json` — **11 элементов**: H, B, C, N, O, F, P, S, Cl, Br, I;
- `core/src/main/resources/chemmod/reactions/default.json` — **5 правил**: `chemmod:complete_combustion`,
  `chemmod:alkene_hydrogenation`, `chemmod:alkane_dehydrogenation`, `chemmod:carbonyl_hydrogenation`,
  `chemmod:alcohol_dehydrogenation`;
- `core/src/main/resources/chemmod/materials/catalog.json` — 3 species (`water`, `oxygen`,
  `carbon_dioxide`), 2 минерала (`native_copper`, `quartz`), 1 жила, 2 материала (`copper`,
  `silicate_gangue`), 21 процесс.

Вывод: 11 элементов и 5 правил порождают пространство структур, а не «три вещества в списке».
Перечня соединений, сплавов или минералов в репозитории нет, и новые пункты плана не должны
его создавать — ни в электротехнике, ни в энергетике, ни в контейнерах.

## 3. Расхождения, найденные при сверке с кодом

1. **Si отсутствует в таблице элементов.** `chemmod:quartz` объявляет `"elementStoichiometry": {"Si": 1, "O": 2}`,
   тогда как `elements.json` содержит только H, B, C, N, O, F, P, S, Cl, Br, I. Кремниевая
   цепочка §8.6/§18.6/H2 упирается в контент: по §14 плана это «апдейт контента, не ядра».
2. **Стехиометрия минералов не сверяется с таблицей элементов.** `MineralDefinition` проверяет
   только соответствие ключей regex `[A-Z][a-z]?` (`Definitions.kt`, строка 48), поэтому кварц
   с неопределённым Si проходит валидацию молча. Прежде чем добавлять кремниевые процессы,
   эту проверку стоит закрыть — иначе контент сможет расходиться без ошибки.
3. **§12 API `mol.canonicalId() -> Long`** против реализации: сохраняется полный digest графа,
   а `Long` — только компактное значение для отображения/API (`Canonicalizer.kt`). Не конфликт,
   а уточнение: хеш-коллизия не может сделать два разных графа одним веществом.
4. **§11 G4 требует админ-команды `/chem give|inspect`.** Действующее решение ChemMod — игровой
   JAR диагностических `/chem`-команд не регистрирует (`docs/architecture.md` §3), проверка ядра
   живёт во внутреннем CLI и CI. Расхождение открыто и закрывается только словом владельца.

## 4. Что из этого следует для следующих срезов

- Порядок, совместимый и с планом, и с текущим состоянием (M3 + аппаратная лаборатория):
  сначала реальное лабораторное оборудование (источники тепла с расходом топлива, вакуум,
  посуда и мебель), затем §8.1 контейнеры, затем §5 газы. Электроника §8.6 — отдельный эпик E0,
  и начинается он с элементов и правил, а не с предметов.
- Форма любого нового пункта: **элемент(ы) → правило(а) → процесс/аппарат**. Перечня готовых
  соединений не появляется ни на одном шаге.
- Чистота и tier — не табличные поля: это `MaterialBatch`/`MaterialMassComposition`
  (точные микрограммы + именованные примеси), из которых tier выводится правилом. Это прямо
  закрывает приёмку H2 («каждая стадия имеет массу/чистоту, нечистый кремний даёт брак/низкий tier»)
  без единой строчки хардкода.
