# ChemMod

Предиктивное физико-химическое ядро и игровой мод для Minecraft 1.21.1/NeoForge.
Вместо каталога захардкоженных веществ проект представляет вещество молекулярным
графом и выводит его идентичность и свойства из структуры.

> Состояние: **M0 готов; M1/M1.5, M4 физического медного обогащения и M5-адаптер
> Create реализованы в игровом NeoForge-каркасе**. Пользовательский артефакт — только мод
> `.jar`; CLI остаётся внутренним инструментом разработчика и не включается в релизы.

## Модули

- `core` — независимая от Minecraft Kotlin-библиотека: молекулярный граф,
  SMILES-подобный парсер, валидация, канонический ID, формула, молярная масса,
  чистый вычислитель свойств, интерпретатор правил реакций с точной балансировкой,
  планировщик дискретных реакционных партий и типизированный каталог
  **материалов**/процессов.
- `core-cli` — внутренняя командная строка для автоматической проверки ядра;
  игрокам она не распространяется.
- `mod` — NeoForge-мод. В первой тестовой сборке содержит внутриигровую команду
  `/chem test`, запускающую молекулярное ядро и балансировщик реакций.

Базовый контент химического ядра находится в JSON, а не в реестре веществ или
коде алгоритмов: элементы — `chemmod/elements.json`, коэффициенты модели свойств —
`chemmod/properties/default.json`, правила реакций — `chemmod/reactions/default.json`,
а тривиальные имена — `chemmod/names/trivial.json`. В базовом M1-наборе пять
правил: общее сгорание, гидрирование/дегидрирование C–C и обратимые переходы
карбонил/спирт. Эти схемы являются основой для будущей загрузки datapack: отсутствие
имени не запрещает существование валидной молекулы, поскольку её идентичность задаёт
канонизированный граф. Метаданные первого синтеза лежат в отдельном `DiscoveryRegistry`,
ключуемом полным canonical key; они не меняют саму молекулу или её свойства.

## Требования

- JDK 21
- Git

Использовать системный Gradle не требуется — репозиторий содержит Gradle Wrapper.

## Проверка

Полная быстрая проверка одной командой (компиляция, unit-тесты и реальные вызовы CLI):

```bash
./scripts/smoke-test.sh
```

Отдельные команды:

```bash
./gradlew check
./gradlew :core-cli:run --args="lookup CCO"
./gradlew :core-cli:run --args="balance 'CCO + O=O -> O=C=O + O'"
./gradlew :core-cli:run --args="react C=CC chemmod:alkene_hydrogenation 350 '[H][H]' --catalyst chemmod:palladium"
```

`smoke-test.sh` запускает dedicated server дважды: сначала **без** Create, затем с
Create 6.0.10 на runtime classpath. Это одновременно проверяет, что адаптер
действительно включается с Create и что обычный ChemMod не получает обязательной
зависимости. Для локального dev-запуска без Create можно передать
`-Pchemmod.createRuntime=false`.

Балансировщик использует точную рациональную линейную алгебру, приводит ответ к
минимальным положительным целым коэффициентам и сохраняет атомы и формальный
заряд. Для примера выше результат — `C2H6O + 3 O2 -> 2 CO2 + 3 H2O`.

Ожидаемый результат для этанола (`CCO`):

- формула `C2H6O`;
- молярная масса около `46.069 g/mol`;
- предсказанная M0-моделью температура кипения около `64 °C`;
- тот же canonical ID для эквивалентной записи `OCC`;
- другой canonical ID и температура для изомера `COC`.

Значение 64 °C является зафиксированным результатом приближённой игровой модели,
а не справочной экспериментальной температурой этанола.

## Поддерживаемый синтаксис M0

Парсер намеренно не пытается реализовать весь стандарт SMILES. Сейчас доступны:

- элементы `B C N O F P S Cl Br I`;
- связи `-`, `=`, `#`;
- ветви в круглых скобках;
- одноцифровые замыкания циклов;
- простые bracket-атомы, например `[NH4+]` и `[O-]`.

Ароматика, стереохимия, изотопы и координационная химия относятся к следующим
этапам.

## Тест в Minecraft

1. Установить Minecraft 1.21.1 и NeoForge 21.1.251 или новее в линии 21.1.
2. Положить релизный `chemmod-....jar` в папку `mods`.
3. Запустить мир с разрешёнными командами.
4. Выполнить одну из команд:

```text
/chem help
/chem lookup вода
/chem lookup H2O
/chem lookup CO2
/chem lookup этанол
/chem balance C2H5OH + O2 -> CO2 + H2O
/chem give этанол
/chem catalog
/chem test
```

`lookup` принимает обычные названия, распространённые однозначные формулы и
структурную запись. `balance` подбирает минимальные целые коэффициенты реакции,
`catalog` загружает, проверяет и показывает канонические материалы и процессы,
а `test` запускает общую администраторскую самопроверку. Формулы, которые
не задают единственную структуру (например `C2H6O`: этанол или диметиловый эфир),
намеренно не используются как псевдонимы.

### Первая игровая колба

В творческом инвентаре появилась вкладка **ChemMod** с пустой колбой и чистыми
(100%) эталонными колбами воды, кислорода, водорода, CO2, метана, метанола,
этанола, диметилового эфира, пропана, уксусной кислоты и хлора. Это один
универсальный предмет с
версионируемым data component: полный canonical key молекулярного графа,
проверяемое структурное свидетельство для его восстановления, количество в
микромолях и чистота в ppm сохраняются прямо в ItemStack и синхронизируются
сервером. Схема v4 проверяет, что key и граф действительно соответствуют друг
другу; старые схемы автоматически получают key при чтении сохранения.

Пустая колба создаётся бесформенным рецептом из стеклянной бутылочки и железного
самородка. ПКМ пустой колбой по источнику воды берёт пробу `H2O` объёмом 1 моль;
источник воды при этом не исчезает. Базовый состав задаётся биомом (океан,
болото, река, снежная зона или обычная пресная вода), затем сервер исследует
блоки в радиусе двух метров, высоту и погоду. Почва и осадок повышают долю
взвесей, растительность — органики и газов, посевы — питательных веществ, руды и
лава — минералов; подземная вода получает следы вымывания, дождь — поверхностного
стока. Результат и причины сохраняются в колбе и не пересчитываются в тултипе.

Тултип показывает доли солей/минералов, газов, органики, питательных веществ и
взвесей, а также обнаруженные факторы окружения. Optional-адаптер TerraFirmaCraft
распознаёт `tfc:salt_water`, `tfc:river_water`, `tfc:spring_water` и варианты
fresh/finite/flowing без импорта классов TFC: солёная вода получает океанический
профиль, речная — речной, родниковая — минеральный. Это честные укрупнённые
игровые группы, а не выдуманный точный химический анализ конкретного блока.

Администратор может создать колбу командой:

```text
/chem give вода
/chem give CO2
/chem give этанол
```

В подсказке отображаются название, формула, количество, чистота и молярная масса.
При включённых расширенных подсказках (`F3+H`) также показываются структурное
свидетельство и полный канонический key.

### Первые канонические формы меди

Каталог автоматически регистрирует десять обычных медных форм: кусок самородной
руды, дроблёную и промытую дроблёную руду, пыль, слиток, самородок, пластину,
стержень, проволоку и шестерню; отдельно доступен размещаемый складской блок меди.
Эталонные экземпляры
из creative создаются с чистотой **100 %**. Каждая форма хранит серверный data
component `chemmod:material_batch` с ID материала, формой и точными массами
первичного материала/известных примесей; чистота вычисляется для отображения.
Предметы имеют собственные встроенные текстуры и входят
в общие `c:`-теги (`ingots/copper`, `dusts/copper`, `plates/copper`,
`gears/copper`, `storage_blocks/copper` и другие), но контент TFC пока не
отключается.

Руда самородной меди ChemMod генерируется data-driven жилами в новых чанках
обычного мира между Y=-32 и Y=80. Для добычи требуется каменная кирка или лучше;
блок руды выдаёт канонический кусок руды с `material_batch`. Существующие чанки не
перегенерируются, а генерация и руды TFC остаются нетронутыми.

Каменная ступка создаётся из пяти блоков, входящих в
`#minecraft:stone_crafting_materials`. Установите её и щёлкните по ней правой
кнопкой с куском руды: первый проход даёт дроблёную руду, второй — медную пыль.
Это быстрый ранний маршрут; он переносит массу, чистоту и известные примеси без
обнуления.

### Физическое обогащение руды: вода, хвосты и разделение

ChemMod использует полезный игровой принцип многоступенчатой переработки, но **не
копирует** код, рецепты, текстуры, названия или баланс GregTech. У добытой в мире
самородной меди есть точный физический состав: в стандартной партии 1 кг находятся
850 г меди и 150 г силикатной пустой породы. Эталонные creative/admin-предметы
по-прежнему содержат ровно 1 кг чистой меди.

`material_batch` v2 хранит не только отображаемый процент чистоты, а массу
первичного материала и каждого известного компонента в микрограммах. Проценты в
tooltip вычисляются из этой массы; ни один микрограмм не может исчезнуть или
появиться при обработке. Предметы из прежней ppm-схемы v1 автоматически
конвертируются при чтении мира.

Соберите промывочную установку из двух медных пластин, четырёх кирпичей и котла.
Держите дроблёную руду в одной руке, а **проанализированную** колбу воды — в
другой, затем примените руду к установке. Колба расходуется и возвращается пустой.
Мод использует не биом в момент обработки, а фактический анализ, уже сохранённый в
колбе: чистая вода оставляет меньше пустой породы в концентрате, солёная, болотная
или загрязнённая — больше. Вся удалённая порода выдаётся отдельными физическими
**хвостами**; вода не создаёт дополнительную медь.

Для чистой пробы природная партия 850 г Cu + 150 г SiO₂ превращается примерно в
861,632 г промытого концентрата (850 г Cu + 11,632 г SiO₂) и 138,368 г хвостов.
Для пробы с 35 000 ppm примесей концентрат тяжелее и грязнее: около 885,186 г,
а хвостов получается около 114,814 г. Это один и тот же материальный баланс, а не
случайный бонусный дроп.

Затем поместите промытую дроблёную руду в **сепаратор руды**. Он выделяет чистую
медную пыль и оставшуюся силикатную породу отдельными стопками. Сепаратор —
малопроизводительный ранний ручной механизм и каноническая физическая операция;
при установленном Create его теперь дополняет кинетический адаптер того же
процесса, не меняющий состав и выходы.

### M5: optional Create — кинетическое разделение без дублирования рецептов

Адаптер рассчитан на **Create 6.0.10 для NeoForge 1.21.1** и включается только
если этот мод реально установлен. Без Create ChemMod не регистрирует
`kinetic_ore_separator`, его block entity или block item, а условный рецепт не
загружается; сохранения обычного ChemMod остаются пригодны для запуска без Create.
Create при этом не встраивается в JAR ChemMod.

При наличии Create скрафтите **кинетический сепаратор руды** из ручного сепаратора,
двух медных пластин, вала Create и андезитового корпуса. Подведите вал Create к
верхней или нижней грани. Решётчатая передняя грань — вход, противоположная —
выход. Минимальная скорость — средняя категория Create; машина потребляет 4 SU на
RPM. Можно щёлкнуть промытой дроблёной рудой по блоку, чтобы положить одну партию,
и пустой рукой, чтобы забрать ближайший готовый результат. Для автоматизации она
предоставляет обычный NeoForge `ItemHandler`: воронки/Create могут подавать партии
во вход и извлекать результаты с выхода.

Это не статический Create-рецепт и не новый генератор случайных дропов. Перед
началом цикла сервер читает сохранённый `material_batch` входного предмета,
резервирует место для всех выходов, а по завершении извлекает ровно одну партию и
выпускает её фактическую массу первичного материала и каждого именованного
компонента. Внутренний буфер имеет 65 выходных слотов — один для первичного
продукта и до 64 примесей, то есть полный допустимый состав schema-v2. Если места
нет, вход не расходуется. Продолжительность берётся из того же канонического
`chemmod:separating` процесса и масштабируется фактической скоростью вращения.
Ни чистота воды TFC, ни материал, ни масса не переопределяются Create-слоем.

Интеграция использует только публичный API Create для вала, kinetic network и
stress impact. Код, ассеты, названия механизмов и таблицы рецептов Create не
переносились; конкретный баланс сборки намеренно остаётся вне ChemMod.

Текущий порядок маршрутов:

```text
быстрый:    руда → дроблёная руда → пыль с примесями → расплав → слиток с примесями
полный:     руда → дроблёная руда → промывка + хвосты
            → промытая дроблёная руда → сепаратор + остаточная порода
            → чистая медная пыль → расплав → чистый слиток
```

После честного разделения одна природная партия содержит только 850 г меди, поэтому
для стандартного килограммового слитка может понадобиться накопить несколько
партий. Огнеупорная печь теперь объединяет совместимые расплавы в тигле до 9 кг, а
изложница отливает ровно 1 кг и возвращает точный остаток расплава вместо потери
или дублирования массы.

Для завершения цепочки создайте керамический тигель, огнеупорную печь и изложницу.
Держите медную пыль в одной руке, древесный уголь — в другой, а пустой тигель — в
инвентаре, затем примените пыль к печи. Полученный тигель хранит жидкую форму,
температуру, массу, чистоту и примеси. Применение расплава к изложнице возвращает
пустой тигель и создаёт слиток. Оба перехода берутся из `chemmod:melting` и
`chemmod:casting` канонического каталога. Тигель является переносимым накопителем
партии, но сами блоки не имеют скрытого инвентаря или таймера обработки.

Для холодной обработки используется верстак металлообработки. Слиток в основной
руке и кузнечный молот в другой дают пластину. Волочильная доска превращает
слиток в стержень, а стержень — в проволоку. Зубило делит слиток на восемь
самородков по 125 г, а восемь самородков молотом снова собираются в слиток.
Из пластины зубилом вырезается шестерня. Все готовые медные формы — слиток,
самородки, пластина, стержень, проволока и шестерня — можно повторно расплавить
в тигель без потери массы, чистоты или примесей.

Цепочка меди теперь замкнута и для складской формы: удерживайте в одной стопке
**9** одинаковых медных слитков и кузнечный молот во второй руке, затем примените
стопку к верстаку — получится складской блок массой 9 кг. Он является настоящим
размещаемым блоком: его block entity сохраняет массу, чистоту и известные примеси
при установке, сохранении мира, добыче и подборе. Чтобы снова получить металл,
используйте этот блок-предмет с зубилом на верстаке: получится 9 слитков той же
партии. Переходы `forming_hammer`, `drawing` и `cutting` загружаются из каталога,
а runtime проверяет требуемое число входных предметов в удерживаемой стопке и
выводит понятное сообщение, если их недостаточно. Количество — часть
канонического процесса, поэтому общая масса сохраняется строго: 1 кг на всех
однокилограммовых маршрутах и 9 кг в маршруте складского блока.

## Архитектурные границы

ChemMod — единый авторитетный центр веществ, минералов, месторождений, руд,
материалов, металлов, сплавов, форм, металлургических процессов и worldgen policy
целевой сборки. Сторонние моды сохраняются ради уникальных машин и механик и
подключаются только через односторонние optional-адаптеры; их дублирующий контент
можно отключать лишь после появления полноценной канонической замены ChemMod.

`core` не импортирует Minecraft или NeoForge API. Командный интерфейс остаётся
диагностическим инструментом, а не пользовательским продуктом. Первый слой M1.5
уже разделяет `ChemicalSpecies`, `MineralDefinition`, `DepositDefinition`,
`MaterialDefinition`, `MaterialBatch` и `ProcessDefinition`. Независимый
`ProcessCompiler` разрешает стабильные ID материалов и отклоняет процессы с
неподдерживаемыми формами до их передачи игровому runtime или адаптерам.
Версионированный `chemmod/materials/catalog.json` уже содержит первый сквозной
срез: воду/кислород/CO₂, самородную медь, политику месторождения, канонические
формы меди и процессы дробления, плавления и литья. Загрузчик проверяет дубликаты,
ссылки, циклы композитов и компилируемость каждого процесса.

Открытия не являются частью каталога или `Molecule`: чистый core-`DiscoveryRegistry`
хранит только факты первого синтеза по canonical key. В `mod` его сохраняет один
world-wide `DiscoverySavedData` в data storage Overworld. Запись намеренно пока не
вызывается командами или творческими предметами: её может создавать только будущая
реальная машина синтеза, чтобы выдача тестовой колбы не считалась открытием.

Для такой машины уже существует `PureSubstanceReactionPlanner`: он переводит
`ReactionBatchPlanner` в заменяемые data components чистых колб, сохраняет точные
микромольные остатки и создаёт продукты из графа через structural witness. Он не
меняет ItemStack сам и не принимает загрязнённые образцы как «чистые»; смеси будут
добавлены отдельной моделью, а discovery фиксируется только после успешной
транзакции инвентаря.
